# OPP-000002: np.inner via one tensordot GEMM for ndim > 2

Status: performance_validated, shipped as `inner_tensordot`
Sources: numpy/numpy#12778 (open since 2019, duplicate of #619 from 2012)
Evidence: `benchmarks/results/OPP-000002/`

## What is slow, and why

For operands with ndim > 2, np.inner routes through PyArray_MatrixProduct2,
which makes a single BLAS call only when both operands are ndim <= 2 and
otherwise loops per-slice 2-D GEMMs. np.tensordot(a, b, axes=(-1, -1)) is
mathematically identical and reshapes to ONE large GEMM. Maintainer-confirmed
(mattip, 2019) and never fixed upstream in 14 years despite the "naive fix"
being explicitly blessed in-thread.

## Does it reproduce

Yes (numpy 2.4.5, scipy-openblas, fingerprint 8f8198d9abab):

| Case (float64 unless noted) | Stock inner | tensordot | Speedup |
|---|---:|---:|---:|
| (25,25,500) x (10000,500), the reported case | 0.79-2.06 s | 22-161 ms | 7.7-36x |
| (10,10,2000) x (5000,2000) | 313-381 ms | 7.5-42 ms | 9.0-42x |
| (50,4,64) x (20000,64) | 60-77 ms | 8.1-8.5 ms | 7.4-9.2x |
| (5,5,100) x (1000,100), small | 434-699 us | 138-220 us | 3.1-3.2x |
| (25,25,500) x (10000,500) float32 | 326 ms | 24 ms | 13.5x |
| GUARD: (500,500) x (500,500) 2-D | 1.2-1.4 ms | ~same | 0.96-1.04x |
| GUARD: 1-D x 1-D n=1000 | ~1 us | 4.5-5.8 us | 0.20x, must not dispatch |

Run-to-run spread is large because the looped-BLAS path's timing depends on
thread-pool state; the win never fell below 7.7x on the reported shape and
3.1x on the smallest ndim>2 case. End-to-end through pyoverdrive.enable():
18.6x and 23.9x across runs.

## Semantics: the one real trade

Numeric equivalence, not bit-identity: one GEMM sums in a different order
than looped GEMMs. float64 agrees to rtol 1e-9; float32 with zero-mean data
can differ by ~1e-3 absolute under cancellation, which is inherent to
summation reordering at single precision. np.inner promises no bit-stability
across versions or BLAS builds, and upstream's own blessed fix is this same
reroute; still, the path is kill-switchable
(pyoverdrive.disable_path("inner_tensordot")) and documented as comparison
mode "numeric". Peak memory differs: tensordot materializes reshaped copies.

## Predicate (all measured)

Both plain ndarrays, matching dtype in {float32, float64}, ndim > 2 on either
operand, matching contraction length, non-empty. Everything else, including
every 1-D/2-D call, integer dtypes, mixed dtypes, and shape mismatches, falls
back to stock (mismatches raise stock's own error).

## Verdict

Shipped. The 1-D guard case doubles as the honest cost record: a patched
np.inner pays ~0.7 us Python dispatch tax, which halves throughput on
nanosecond-scale 1-D calls; that cost is the strongest argument for the
native-dispatch investigation (spec section 10.5) and is documented in
benchmarks/results/MVP-BASELINE/. Monitor #12778 for upstream movement.
