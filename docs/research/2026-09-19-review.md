# PyOverdrive consolidation and review — 2026-09-19

## Why there were two checkouts

The original checkout was the private development/archive repository. The
public checkout began as a fresh-history export with private steering and
release tools removed. The release assembler explicitly describes this split.
Later development continued on both sides: 411 tracked files were identical,
27 differed, 15 existed only in the archive and one only in public.

The public Git history remains canonical. Twenty-seven reviewed runtime,
test, diagnostics, research and measurement files were recovered from the
archive. Public release metadata, CI triggers and community links were
preserved. Private steering/release material and alternate maintenance-tool
implementations remain in the recoverable local archive, along with both
complete Git-history bundles. No remote repository was changed.

## Confirmed findings and changes

| Priority | Finding | Resolution |
| --- | --- | --- |
| High | Parallel ufuncs accepted shifted overlapping input/output views, allowing one worker to overwrite another worker's unread input. A 300,000-element sin probe had 225,000 incorrect elements. | Reject partial overlap at dispatch and use whole-array stock buffering in the core. Exact in-place and disjoint aliases remain supported. |
| High | A NumPy warning promoted to an exception was treated as an accelerator failure and retried on already modified in-place input. | Preserve the original warning exception and avoid replay. |
| High | Search-query sorting changed stock results for an unsorted haystack on NumPy 2.4.5. | Recover the archive's complete sortedness guard and differential tests. |
| Medium | A bad activation target could leave NumPy partially patched while `enabled()` was false. | Prepare replacements before mutation and roll back assignment failures, preserving pre-existing activation. |
| Medium | A saved calibration could re-enable a path explicitly disabled through the environment. | Give the environment kill switch precedence. |
| Medium | Valid JSON with an invalid calibration structure could crash package import. | Validate top-level and machine records before reading them; ignore invalid records. |
| Medium | Running tests in the public directory could import the archive's editable installation and stale version metadata. | Set pytest's source path to this checkout and reinstall the canonical development environment. |
| Performance | The public copy missed measured conservative guards already present in the archive. | Recover unique/intersect minimum sizes, per-test-set isin floors, the relayout floor and int64 searchsorted withdrawal, with matching fixtures and diagnostic inputs. |
| Performance | NumPy >=2.0 admitted old versions lacking the BLAS routing that split-complex matrix multiplication depends on. | Require >=2.3 and test the exact 2.3.0 floor in CI. [Upstream implementation](https://github.com/numpy/numpy/pull/23752). |
| Tooling | The public performance sweep omitted several calibration rows and cardinality cases; tiled growth distorted some inputs. | Recover row/value/shape coverage, distribution-aware input growth, cross-version checks and evidence-provenance checks. |
| Tooling | Failed child sweeps could produce a false success, and cached latest-version environments could stay stale. | Require completion/coverage evidence and fresh latest-version installation; regression tests exercise child-process failures. |

## Evidence and limits

Before changes, explicitly loading the public source produced **2,207 passed,
2 skipped and 1 expected failure**, with Python 3.14.2 / NumPy 2.4.5. Ordinary
system Python instead loaded the archive source and reported 0.0.1.dev0; a
packaging test reproduced this mismatch. The earlier note about 50 red tests
was therefore not a trustworthy baseline for the public source itself.

New regressions were observed failing before their fixes: 11 overlap cases,
4 warning-replay cases, 11 activation cases and 7 calibration cases. The
300,000-element overlap probe then returned zero mismatches.

Performance guard changes are recovered prior work, not newly derived speedup
claims. No accelerated numerical kernels were replaced. CPU utilization was
31.8% during this review, exceeding the project's 20% quiet-machine threshold;
a new end-to-end speedup claim would not be justified by this session.

The archived evidence also contains unresolved low-cardinality losses and
cross-machine uncertainty. These remain explicitly tracked in the single
[open-work list](../todo/TODO.md), together with 19 legacy performance claims
that still need NumPy-version provenance. Nested calibration payloads also
need additional schema validation beyond the top-level safeguards fixed here.
Full performance re-calibration is
separate from the correctness and packaging checks performed here.
